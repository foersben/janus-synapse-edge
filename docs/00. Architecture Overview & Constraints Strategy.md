# 00. Architecture Overview & Constraints Strategy

## 1. The Hardware Reality & Constraints

This server is built on a philosophy of Constraint Engineering. We are building an enterprise-grade autonomous AI cluster on consumer-grade hardware within a thermally constrained Micro-ATX chassis. Understanding the bottlenecks is critical to the software design. The Fixed Hardware Profile:

* **CPU:** Intel Core i7-14700K (20 Cores: 8 P-Cores / 12 E-Cores).
* **RAM:** 128GB Crucial DDR5. Advantage: Massive capacity for model offloading.
* **GPU:** ZOTAC RTX 5070 Ti (16GB VRAM). **Superpower:** This is a Blackwell (SM120) architecture GPU. It contains 5th-generation Tensor Cores capable of native hardware-accelerated NVFP4 (4-bit floating point) inference, effectively behaving like a 32GB+ card for supported models.
* **Chassis:** Jonsbo Z20 (Micro-ATX). Constraint: Highly restricted thermal dissipation for sustained 280W+ CPU loads.

## 2. The "Dual-Engine" Philosophy (The NVFP4 Paradigm)

Because a standard 70B parameter model in FP16 requires ~140GB of memory, it cannot fit into the 16GB RTX 5070 Ti. The software stack relies on a bifurcated, highly optimized system leveraging Blackwell's NVFP4 precision:

* **Engine A (The Deep Orchestrator):** Uses **PowerInfer** for 70B reasoning models quantized to NVFP4. The NVFP4 format shrinks the 70B model to a mere ~35GB footprint. PowerInfer maps the "hot" neurons to an 11GB VRAM budget and spills the "cold" neurons to the DDR5 RAM. This drastically minimizes PCIe bottlenecking and unlocks datacenter-level speeds.
* **Engine B (The Rapid Executor):** Uses **SGLang** to run hyper-optimized 7B–8B models (e.g., `Qwen-2.5-7B`). By utilizing native NVFP4 weights, the entire model only consumes ~4GB of VRAM. It fits *entirely* within the GPU alongside Engine A, handling continuous tool-calling, API fetching, and UI responses instantly with zero system RAM latency.

## 3. Security & Virtualization Strategy

* **Zero-Trust Bare Metal:** The Proxmox host runs nothing but the hypervisor. It is fully ZFS encrypted.
* **Direct Hardware Access:** The GPU is not shared via vGPU slicing. It is passed entirely via PCIe (IOMMU) to a secure, isolated Talos Linux VM running Kubernetes (K3s).
* **Kubernetes Orchestration:** AI inference engines and databases run as isolated Pods, managed by ArgoCD, allowing for rapid, zero-downtime updates as the AI software landscape evolves.

## 4. The Zero-UPS & Edge-Node Resilience Strategy

Because a high-end UPS capable of sustaining a 400W+ AI load is cost-prohibitive, the architecture embraces a "Crash-Safe" philosophy.

* **The Main Server:** Expected to lose power instantly during an outage. We rely on immutable OS layers (Talos), GitOps (ArgoCD), and strict API routing to ensure the server never corrupts its base configuration.
* **The Edge-Node (Intel NUC):** The system's "Long-Term Memory" (SurrealDB) is physically detached from the compute node and moved to an Intel NUC10i5FNH. The NUC is backed by an Eaton 3S 550 DIN UPS, ensuring the database never experiences an ungraceful shutdown and further protecting the NVMe from index shattering.
* **Network Backbone:** The NUC and main server communicate via a **NETGEAR MS308E 2.5G Multi-Gigabit Managed Switch**.
* **NUC Connectivity:** Because the NUC10 natively only supports 1Gbps, it is upgraded with a **UGREEN 2.5G USB-C LAN Adapter** to match the switch’s 2.5Gbps throughput, removing the primary bottleneck for GraphRAG traversals.
