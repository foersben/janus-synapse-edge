# 10. Observability, Telemetry & GitOps

*An autonomous AI server is a black box. If an agent burns through 50,000 tokens while you sleep, or if the 14700K starts thermal throttling, you need precise telemetry to diagnose it. Furthermore, you need a safe way to update the software dynamically without breaking the AI's short-term memory cache.*

## 1. LLM Tracing & Agent Observability (Langfuse)

You cannot rely on simple terminal logs to understand what an autonomous agent is "thinking."

* **Deployment:** Deploy the **Langfuse** open-source container in your Kubernetes cluster, backed by your Postgres pod.
* **The LiteLLM Connection:** Configure your LiteLLM proxy to natively export all telemetry data to Langfuse.
* **MCP Tracing:** Because NemoVision operates as a separate Model Context Protocol (MCP) server, ensure Langfuse spans are configured to trace the exact visual data NemoVision extracts before it is passed back to the core agents.
* **The Dashboard:** Langfuse provides a visual "Waterfall" UI. You can click on a specific task (e.g., "Write a scraper") and visually trace exactly what Agent Zero thought, what tools NemoClaw called, exactly how many milliseconds each step took, and where a prompt failed.

## 2. Bare-Metal & Network Telemetry (Prometheus & Grafana)

Because we are pushing a Micro-ATX thermal envelope and rely on distributed hardware (The NUC), standard OS monitoring is not enough.

* **Deployment:** Install `node-exporter` on the Proxmox host, a lightweight exporter on the Debian NUC, and run Prometheus/Grafana in your K3s cluster.
* **Custom Grafana Dashboards Required:**
    1. **PowerInfer Sparsity Monitor:** Track the PCIe bus bandwidth. You need to verify that PowerInfer is correctly keeping "hot" NVFP4 neurons on the RTX 5070 Ti and only spilling "cold" neurons to the Talos Hugepages.
    2. **VRAM Saturation:** An alarm must trigger if Engine B (`SGLang`) hits 98% VRAM usage, allowing you to tweak the context limits before an Out-of-Memory (OOM) crash occurs.
    3. **P-Core Thermals:** Specifically monitor Cores 0-7 (The P-Cores) on the 14700K. If they sit at 95°C+ during a multi-hour AlphaEvolve training loop, you must lower the PL1/PL2 wattage in the ASRock BIOS.
    4. **Edge-Node Database Latency:** Monitor the Gigabit switch traffic and the ping to the Intel NUC. If SurrealDB micro-writes begin taking longer than 5ms, the network switch is bottlenecking the inference engines.

## 3. GitOps, Hot-Reloading & Mono-Repo Architecture

The AI software landscape moves at breakneck speed. You must never manually run `kubectl apply` or SSH into the server. We use a strict GitOps Mono-Repo, separated into Infrastructure (Cold-Restarts) and Agent Logic (Hot-Reloading).

* **The Principle:** Your entire server configuration lives as plain text files in a local Gitea repository. **ArgoCD** watches this repository and automatically syncs changes to the K3s cluster.
* **The Mono-Repo Folder Structure:**
  * `/infrastructure`: Contains `talos-machineconfig.yaml`. Used only for bare-metal OS recovery.
  * `/cluster-tools`: Contains foundations like ArgoCD manifests, NVIDIA device plugins, and OpenEBS storage classes.
  * `/apps`: Contains your core engines `/inference` (PowerInfer/SGLang), `/gateways` (LiteLLM/n8n), and `/ui` (AnythingLLM).
  * `/agents`: Contains your dynamic logic: Python tool scripts, CrewAI roles, and system prompts.
* **The Atomic Update Flow (Protecting the VRAM Cache):** * **Infrastructure Updates:** If you change an engine parameter in `/apps` (e.g., giving SGLang more VRAM), ArgoCD safely destroys the old pod and rolls out a new one.
  * **Agent Updates (Hot-Reloading):** When the `AlphaEvolve` loop commits a better system prompt to the `/agents` folder, ArgoCD does *not* restart the SGLang container. Instead, ArgoCD syncs the new text file into a Kubernetes `ConfigMap`. The agent pods mount this ConfigMap as a live folder and instantly "hot-reload" the new logic. **This prevents the massive VRAM Cache-Augmented Generation (CAG) memory from being flushed**, avoiding severe cold-start penalties during autonomous training.
