# 02. Proxmox Base Installation & ZFS Encryption

## 1. The Installation Media & OS Goal

The goal of this layer is absolute minimal footprint and maximum data security. Proxmox is a Type-1 Hypervisor based on Debian. **Do not install any software directly onto this host.** It exists solely to manage hardware routing, hold the ZFS encryption keys, and host the Virtual Machines.

1. Download the latest Proxmox VE ISO.
2. Flash it to a USB stick.
3. Boot the server from the USB stick and select "Install Proxmox VE".

## 2. ZFS Native Encryption (Securing Data at Rest)

During the installation wizard, when prompted for the Target Harddisk, do not click "Next" immediately. Click **Options**.

* **Filesystem:** Change this from `ext4` to **`zfs (RAID0)`**. Even though you only have a single 2TB FireCuda 530, ZFS provides critical bit-rot protection, checksumming, and instant snapshot capabilities.
* **Advanced Options:** Click the advanced tab.
* **Encryption:** Enable **ZFS Native Encryption** (AES-256-GCM).
* **Key Format:** Select **Passphrase**.
    * *Security Note:* Choose a strong passphrase. You will need a directly attached USB keyboard to type this password every single time the server boots or reboots.
* **Complete Install:** Finish the wizard, set your static IP address, and let the system reboot.

## 3. The Boot & Unlock Process (Strict Physical Air-Gap)

If the server loses power or is stolen, it is functionally a brick.
Upon booting, the screen will halt at a terminal prompt asking for the ZFS passphrase. Once typed, the hypervisor unlocks the SSD, mounts the datasets, and starts the web interface on port `8006`.

* **STRICT WARNING against Remote Decryption:** Do not attempt to bypass this physical security measure by installing remote unlock tools like `dropbear-initramfs`. Automating the ZFS decryption key via network transmission completely breaks the "Zero-Trust Bare Metal" mandate. You must accept a "Human-in-the-Loop" requirement for cold boots to guarantee physical data security
