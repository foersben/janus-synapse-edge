# Multi-Tenant Profiles and Privacy Tiers

Operating a centralized AI cluster that services both highly sensitive personal queries and generalized professional development tasks requires strict "Brain-Mixing" prevention. The Janus architecture enforces software-defined multi-tenancy at the memory substrate and network egress layers.

---

## 1. Epistemological Isolation (SurrealDB & Hindsight)

To prevent an autonomous agent from bleeding context between operational profiles (e.g., pulling a personal financial record while generating Python code for a client), strict namespace scoping is enforced at the database level.

* **Cryptographic Namespacing:** Every distinct user or operational profile is assigned a discrete SurrealDB Namespace (e.g., `ns: architect` versus `ns: partner`). Agents are provisioned with dynamically generated, scoped RPC credentials that cryptographically authorize access solely to their designated namespace.
* **Hindsight `user_id` Filtering:** Every retrieval request initiated by the proxy includes a mandatory `user_id` header. The Hindsight memory engine strictly filters the semantic vector search and graph traversal algorithms, restricting node retrieval strictly to the authenticated ID. This ensures personalized context without epistemological cross-contamination.

---

## 2. Software-Defined Egress Governance

We categorize all incoming workloads into distinct "Sensitivity Tiers" to determine internet egress authorization.

### Tier 0: The "Private" Enclave
* **Workload Scope:** Highly personal datasets, financial analysis, or sensitive psychological profiling.
* **Routing Enforcement:** These tasks are hard-routed by LiteLLM exclusively to **Local Inference Only (Engine A)**.
* **Network Execution:** The LiteLLM configuration for Tier 0 profiles contains a hardcoded `egress: block` directive. It is mathematically impossible for data processed in this tier to traverse the external firewall; it never leaves the local 2.5G backbone.

### Tier 1: The "Professional" Enclave
* **Workload Scope:** General developer tasks, boilerplate code generation, or public API research.
* **Routing Enforcement:** Tasks in this tier are permitted to utilize remote, high-capacity commercial LLMs (e.g., Anthropic Claude, OpenAI).
* **Sanitization:** Before the prompt is permitted to leave the cluster, it must pass through two strict pre-processors:
    1. **PII Masking Filter:** Algorithmically redacts identifiable names, IPs, and local paths.
    2. **Hindsight Tag Filter:** Only context nodes explicitly tagged as `privacy: public` in the SurrealDB ledger are allowed to be appended to the outgoing payload.

!!! danger "The Danger of Egress Misconfiguration"
    If the Hindsight Tag Filter fails, an autonomous agent (like NemoClaw) could accidentally inject a private API key from its long-term memory into an outbound Anthropic request. The two-stage sanitization pipeline is mandatory for all Tier 1 execution.

## 3. Resource Suitability and Temporal Priority

All AI reasoning (Engine A and Engine B) executes within the **Tensor Worker (VM 1)** to access the RTX 5070 Ti and the P-Core allocation. Because physical cores cannot be deeply partitioned between multiple active tenants without destroying inference latency, priority is managed via temporal Kubernetes preemption.

| Architectural Component | Operational Status | Multi-Tenant Suitability and Execution Priority |
| :--- | :--- | :--- |
| **Intel P-Cores (0-15)** | **Critical Engine** | Hosts all bare-metal inference. Interactive human chats (`Priority: System-Critical`) instantly preempt background agent processes (`Priority: Background-Yield`), granting exclusive physical core access to the active tenant. |
| **Intel E-Cores (16-25)** | **Support Mesh** | Dedicated exclusively to the Orchestration Layer (LiteLLM, n8n, K3s Control Plane). Manages concurrent routing for all users simultaneously without interrupting the GPU compute cycles. |
| **128GB DDR5 RAM** | **Capacity Superpower** | Vast capacity permits both the 70B and 8B models to remain permanently resident in memory via PowerInfer sparsity offloading, eliminating "Cold Start" lag when switching between tenant profiles. |
| **RTX 5070 Ti VRAM** | **The Narrow Bottleneck** | The 16GB VRAM limit is the most constrained resource in the cluster. Strict `--mem-fraction-static` fencing is absolutely required to prevent Out-of-Memory (OOM) kernel panics when multiple heterogeneous engines are active. |
