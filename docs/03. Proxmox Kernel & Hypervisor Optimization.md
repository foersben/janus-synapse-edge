# 03. Proxmox Kernel & Hypervisor Optimization

*Crucial: By default, Proxmox will allocate 50% of the system's RAM to cache disk reads, which will instantly crash  AI models when they try to load.*

## 1. Taming the ZFS ARC Cache

We must restrict ZFS from eating the 128GB DDR5 pool so `llama.cpp` has room to breathe.

1. Log into the Proxmox Web UI (https://YOUR_IP:8006).
2. Click your Node name on the left, then click **Shell**.
3. Create/edit the ZFS configuration file: `/etc/modprobe.d/zfs.conf`
4. Paste the following line to hard-limit the ARC to 8GB (Maximum) and 2GB (Minimum):
   `options zfs zfs_arc_max=8589934592 zfs_arc_min=2147483648`
5. Save and exit
6. Apply to kernel: `update-initramfs -u -k all`

## 2. The Swap Destruction (Protecting the NVMe)

If the 128GB of RAM fills up completely, Linux will default to "swapping" memory pages to the NVMe drive. Writing a 40GB LLM to a consumer SSD will freeze the server for 10 minutes and quickly destroy the drive's TBW endurance. We want the system to OOM-kill (crash) the AI pod instantly rather than swap.

1. In the Shell, run: `swapoff -a`
2. Remove the swap volume completely: `lvremove /dev/pve/swap` (Type 'y' to confirm).
3. Open `/etc/fstab` and comment out (`#`) any line referencing a swap partition.

## 3. Strict Hypervisor Boundaries (Memory & CPU)

* **RAM Allocation:** Proxmox is strictly limited to 12 GB of RAM (8 GB for the ZFS ARC limit configured above, and 4 GB for the Debian base OS). We do not configure Hugepages at the Proxmox level, as this would lock physical memory away from the VMs.
* **CPU Scheduling:** We rely on strict, deterministic core-pinning (taskset) at the hypervisor level. Do not attempt to install experimental eBPF schedulers (like scx_rustland) on the Proxmox host. Deterministic hardware isolation is vastly superior for our "Dual-Engine" virtualization setup.
* **Host CPU Pinning (The "Ghost" Threads):** The 14700K has 28 total threads (0-27). VM 1 uses 0-15 and VM 2 uses 16-25, leaving threads 26 and 27 untouched. We must explicitly restrict the Proxmox host OS to only use these two remaining E-Cores to handle ZFS encryption and 2.5G network I/O.
    * Edit `/etc/systemd/system.conf` and set `CPUAffinity=26 27`. This prevents hypervisor background tasks from interfering with AI inference cycles.
    * Reboot the host. Proxmox is now physically walled off from K3s
