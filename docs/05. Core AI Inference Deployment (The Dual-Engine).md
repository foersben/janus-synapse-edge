# 05. Core AI Inference Deployment (The Dual-Engine)

*Now that the Kubernetes cluster is running, we deploy the actual AI engines as containerized Pods. Everything is defined as YAML files stored in your local Git repository.*

## 1. Engine A: Deep Orchestrator Pod (`PowerInfer`)

* **Role:** 70B parameter reasoning and planning.
* **The NVFP4 + Sparsity Shift:** We deploy the **PowerInfer** engine utilizing the **NVFP4** quantization format. The 4-bit floating-point format shrinks the massive 70B model down to just ~35GB with negligible reasoning degradation.
* **Pod Configuration Security:** To prevent catastrophic swapping, this pod must be granted `IPC_LOCK` capabilities. This allows it to execute the `mlock` command, locking the "cold" neurons securely into the DDR5 RAM.
* **Execution Routing:** Provide the VRAM limit flag (`--vram-capacity 11GB`). This leaves enough room for Engine B and system overhead. PowerInfer will map the vast majority of its "Hot Neurons" directly to the RTX 5070 Ti's 11GB budget, ensuring maximum PCIe bandwidth efficiency, and spill the remaining ~24GB into the mounted Talos Hugepages.

## 2. Engine B: Rapid Executor Pod (`SGLang`)

* **Role:** 7B-8B parameter continuous tool-calling and sub-agent execution.
* **NVIDIA Runtime:** This pod uses the `nvidia-container-toolkit`. Ensure its YAML requests `nvidia.com/gpu: 1` so Kubernetes grants it exclusive access to the RTX 5070 Ti.
* **Hardware-Native Weights & Strict VRAM Capping:** Load models natively compiled for Blackwell (e.g., `modelopt_fp4`). An 8B model natively consumes ~4GB. You must start the SGLang container with a strict `--mem-fraction-static` flag to permanently fence it into a ~4.5GB VRAM footprint. This absolutely prevents SGLang's KV Cache from creeping into the final 1GB of VRAM reserved for Talos and CUDA overhead.
* **Attention Backend & Stability (CRITICAL):** You must add `--fp4-gemm-backend flashinfer_cudnn` to the launch arguments. Relying on the default `flashinfer_cutlass` backend causes `NaN` (Not a Number) crashes under high concurrent load on Blackwell GPUs.
* **NVFP4 KV Caching:** Do *not* use FP8 or experimental 3-bit branches. Enable native **NVFP4 KV Cache**. This leverages the hardware micro-scaling to compress the AI's "short-term memory" by an additional 50% over FP8.
* **The VRAM Effect:** Because the `--mem-fraction-static` flag fences the engine, and NVFP4 severely compresses the KV cache, Engine B safely operates in a bounded state. Your 16GB RTX 5070 Ti can easily host Engine A, the 8B model, and multiple simultaneous NemoClaw agents without ever crossing the 16GB physical limit and risking an Out-of-Memory (OOM) crash

## 3. Local Model Storage (OpenEBS)

Do not use complex distributed storage (like Longhorn or Ceph) for a single physical server. Install **OpenEBS LocalPV**.

* **Sacrificing GDS for Absolute Security:** True NVIDIA Magnum IO (GPUDirect Storage) requires the GPU to bypass the CPU/RAM and speak directly to the physical NVMe controller. Because our 2TB FireCuda 530 is encrypted at the bare-metal level using **ZFS Native Encryption**, Proxmox strictly controls the I/O path. GDS is impossible in this topology.
* **The Storage Reality:** We gladly sacrifice GDS to preserve encryption. OpenEBS LocalPV will use standard hostpaths pointing to our virtualized 1M recordsize ZFS dataset.
* **The Trade-Off:** Reading a 40 GB model into RAM via standard `virtio-blk` or `virtio-scsi` will still easily saturate 3,000 to 4,000 MB/s. A cold boot of our 70B model might take 12 seconds instead of 6 seconds. Once the model is locked into the DDR5 RAM and RTX 5070 Ti, storage speeds no longer matter, and token generation speed is completely unaffected
