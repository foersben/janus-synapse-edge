# 06. Data Layer & Memory Substrate

*Standard RAG (Retrieval-Augmented Generation) using simple Postgres vector extensions is insufficient for long-term agent autonomy. Agents need to understand relationships between facts, not just text similarity.*

## 1. The Edge-Tier Brain: SurrealDB on Intel NUC

To protect the main server's expensive NVMe drive from the brutal write-amplification of autonomous agents, and to survive sudden power losses, the primary database does not live on the Proxmox host.

* **Hardware & OS:** An Intel NUC10i5FNH (i5-10210U) with 16GB RAM and a 250GB NVMe drive. To maximize the 16GB of RAM for the database write-buffer, do not install the Proxmox Hypervisor here. Install a lean, bare-metal OS like **Debian 12 Server**. It is connected to the main Proxmox host via a NETGEAR MS308E Managed Switch for isolated, high-speed routing.
* **Network Hardware:** Connectivity is handled via the **NETGEAR MS308E 2.5G Switch** and a **UGREEN USB-C to 2.5G Adapter** (using the Realtek RTL8156B chipset for native Debian 12 support)
* **Battery Backed:** The Intel NUC **and the NETGEAR MS308E Managed Switch** are both plugged into the Eaton 3S 550 DIN UPS. In case of a power outage, the UPS keeps the database running, preserves the network routing layer, and guarantees the NUC can successfully transmit the Wake-on-LAN magic packet to the main server once grid power stabilizes.
* **Multi-Tenant Namespace Scoping:** To support multiple users and profiles, SurrealDB is partitioned into isolated Namespaces. The "Architect" and "Partner" profiles utilize unique, cryptographically separated namespaces (`ns: architect` vs `ns: partner`) on the NUC's NVMe. Scoped API credentials ensure that an agent fetching context for one workspace can never access the session history of another.

### The *RAM Shock Absorber* (ZFS Asynchronous Mode)

Because the NUC is UPS protected, we can completely ignore standard database paranoia regarding sudden power loss. We use the NUC's RAM as a massive write-buffer to protect the SSD, but we must strictly budget it to prevent an OS crash.

* **Configuration:** The NUC's NVMe is formatted with ZFS. We set the dataset property `zfs set sync=disabled <pool>/surrealdb` and increase the transaction group timeout (`zfs_txg_timeout=120`).
* **The RAM Budget Limit:** We explicitly limit the ZFS ARC cache (`zfs_arc_max`) to **12GB**. This guarantees that the remaining 4GB of physical RAM are permanently reserved for the bare-metal Debian 12 OS, the 2.5G network driver overhead, and the MinIO S3 backup container.
* **The Effect:** SurrealDB executes thousands of tiny micro-writes (graph relationships, agent logs) entirely in the blazing-fast 12GB DDR4 buffer. Every 2 minutes, ZFS neatly packages this memory state and flushes it as one single, highly efficient contiguous block to the NVMe, reducing wear-and-tear by 90%

### Bi-Temporal Memory, GraphRAG & Spectron

* **Hybrid Querying:** SurrealQL allows agents (running on the main server) to perform a single query over the network that combines a semantic vector search *with* a graph relationship traversal (e.g., "Find documents related to 'Python' \[Vector\] -> created by 'Agent Zero' \[Graph\] -> after last Tuesday \[Temporal\]") with only a 1–3ms latency penalty.
* **Append-Only Ledger:** The database acts as an append-only ledger. If an agent learns a fact changes (e.g., "The server IP is now 192.168.1.50"), it doesn't delete the old IP; it records *when* it changed. This prevents agents from hallucinating outdated system states.
* **The Spectron Subsystem:** We utilize SurrealDB's native Spectron memory layer running on the NUC's i5 processor. During your "Idle-Loop / Dreaming" phase at night, Spectron background processes autonomously analyze the knowledge graph to consolidate fragmented facts, infer implicit relationships, and resolve entity ambiguities.
* **Cold Archival Pipeline (Preventing Exhaustion):** Because the database is an append-only ledger operating on a small 250GB NVMe, it will eventually fill up with historical agent logs and DSPy training runs.
    * We deploy a Kubernetes CronJob (The "Archivist") that runs weekly.
    * It queries SurrealDB for non-essential execution logs older than 30 days, exports them, compresses them into `.tar.gz` archives, and moves them to the main server's 2TB FireCuda drive (or S3 bucket). It then deletes the old records from the NUC, ensuring the Edge-Tier Brain never hits 100% disk capacity
* **SSD Upgrade Path:** When upgrading, add a 2.5" SATA SSD to the NUC's empty bay. Use ZFS to mirror the NVMe to the SATA drive, replace the NVMe with a larger unit, and re-mirror. Use the NVMe as the "Hot Tier" (Active DB) and the SATA SSD as the "Cold Tier" (Archives/Backups)

## 2. Hindsight (The Personalization & Entity Engine)

We do not use Mem0, as its graph capabilities are paywalled and its benchmark accuracy is comparatively low. Instead, we deploy **Hindsight** (by Vectorize.io, MIT-licensed) as a lightweight container between the user and the AI.

* **Multi-Strategy Retrieval:** Where standard RAG fails, Hindsight runs four parallel retrieval strategies locally on every query: Semantic Search, BM25 Keyword matching, Graph Traversal, and Temporal Reasoning, merged via a cross-encoder reranker.
* **Structured Beliefs:** Instead of a dumb bag of text snippets, Hindsight separates objective facts from subjective beliefs. It organizes knowledge into distinct memory networks (World facts, Agent Experiences, subjective Opinions, and consolidated Entity Observations).
* **The Goal:** You should never have to repeat yourself. If you correct an agent ("Do not use single quotes in Python, use double quotes"), Hindsight catches this.
* **How it Works:** It algorithmically extracts this preference, resolves the entity, and permanently stores it in SurrealDB as a discrete fact within the Opinion/Observation network.
* **Native MCP Injection:** Whenever you start a new workflow, Hindsight uses its native Model Context Protocol (MCP) integration to silently intercept the prompt and dynamically inject your rules and relevant memory networks into the system prompt of the executing agent
